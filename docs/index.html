architecture

One trust boundary, enforced before execution.

The Agent Loop reasons through an LLM and proposes tool calls. The Guard authorizes each call against capability profiles — denied calls stop before execution. Allowed calls fan out to per-task agents that SSH into in-cluster sandboxes; the same scoped SSH reaches your external servers. Every step lands in PostgreSQL.

capabilities & guardrails

What it does. What it refuses to do.

Fleet diagnostics

Run diagnostics across many hosts from isolated sandboxes; get a clear summary, not raw terminal noise.

Scripted remediation

Restart services or apply playbooks via skills declared in the guard profile. Everything outside the whitelist is rejected.

Specialized sandboxes

base for CLI, browser for web checks, python for scripting, ffmpeg for media, db for SQL.

Guard profiles

Capabilities and command whitelists per host. Deterministic rejection — free-form shell on production never happens.

Constrained SSH

Sandboxes reach your servers over SSH with scoped users and keys configured per connection — not your shell credentials.

Session logs

Every prompt, tool call, step, and guard decision persisted per connection. Queryable in the UI and the database.
